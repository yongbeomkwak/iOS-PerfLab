# 주제 문서 작성 규칙

- 한국어로 쓴다. 블로그에 그대로 올릴 수 있는 문장으로 쓴다.
- 템플릿의 `TODO:`는 내용으로 바꾼다. 남아 있으면 `scripts/perflab validate`가 실패한다.
- **수치는 `results/*.json`과 RESULTS.md 결과표에서만 인용한다.** 기기, OS, 빌드 구성을 함께 적는다.
- 시뮬레이터 결과를 인용할 때는 "참고용"임을 밝힌다.
- RESULTS.md의 `<!-- perflab:results:start/end -->` 사이는 `scripts/perflab table`이 생성한다. 직접 수정하지 않는다.

## LEARNING.md

- 체크포인트마다 `### [Plan]`, `### [Stage N]`, `### [Measure]` 형식의 헤딩으로 기록한다.
- **사용자 답변은 틀려도 고치지 않고 그대로 기록한다.** 예측과 실제의 차이가 이 프로젝트의 핵심 학습 자료다.
- 사용자가 추가로 한 질문과 그 답도 같은 체크포인트 아래에 남긴다.

## SUMMARY.md

- 독자는 iOS 개발자다. 상황 → 문제 → 단계별 해결 → 측정 → CS 지식 → 회고 흐름을 지킨다.
- "필요한 CS 지식"은 이 주제를 이해하는 데 실제로 필요했던 개념만 쓰고, 각 개념이 어느 Stage와 연결되는지 밝힌다.
- "예측과 실제"는 LEARNING.md의 사용자 예측을 근거로 쓴다.
